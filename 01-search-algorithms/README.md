# 01. Алгоритмы обхода и поиска: поиск в ширину и поиск в глубину

## Что такое обход графа и зачем он нужен

Граф — это структура данных из множества **вершин** и соединяющих их **рёбер**. Огромное количество практических задач сводится к графу: лабиринт (клетки — вершины, проходы — рёбра), социальная сеть (люди — вершины, дружбы — рёбра), интернет-страницы со ссылками, состояния игры со ходами.

«Обход графа» — это процедура, которая систематически посещает все достижимые из стартовой точки вершины **ровно по одному разу**. Без слова «ровно» обход рискует уйти в бесконечный цикл, если в графе есть циклы.

Существует два фундаментальных способа обходить граф:

1. **Поиск в ширину** (Breadth-First Search) — сначала посещаем всех ближайших соседей стартовой вершины, потом всех соседей их соседей, и так далее «волнами».
2. **Поиск в глубину** (Depth-First Search) — уходим в одну ветку максимально глубоко, и только когда упираемся в тупик, возвращаемся и пробуем следующую ветку.

Принципиальная разница только одна: в каком порядке мы вынимаем «ещё не обработанные» вершины. Поиск в ширину использует **очередь** (структура «первый пришёл — первый ушёл», First In First Out), поиск в глубину использует **стек** (или эквивалентную ему рекурсию, «последний пришёл — первый ушёл», Last In First Out).

## Сравнительная таблица

| Свойство | Поиск в ширину | Поиск в глубину |
|---|---|---|
| Структура для «фронта работ» | Очередь (FIFO) | Стек или рекурсия (LIFO) |
| Идея обхода | Концентрические кольца от старта | Уход в глубину, откат при тупике |
| Кратчайший путь в **невзвешенном** графе | Находит, и это его главная сила | Не находит — может вернуть длинный путь |
| Топологическая сортировка | Возможна через алгоритм Кана (по входящим степеням) | Классический способ — через моменты выхода |
| Поиск циклов | Возможен, но менее удобен | Удобно через раскраску вершин в три цвета |
| Память в худшем случае | O(V) — очередь может содержать целое «кольцо» вершин | O(h) — глубина рекурсии или стека |
| Время | O(V + E) | O(V + E) |

Здесь и далее: V — количество вершин, E — количество рёбер.

## Поиск в ширину — подробный разбор

### Идея

Представь, что ты бросил камень в воду в стартовой вершине. Расходящиеся круги — это уровни обхода. На уровне 0 — только сама стартовая вершина. На уровне 1 — все её прямые соседи. На уровне 2 — все вершины, до которых нужно сделать ровно два перехода по рёбрам. И так далее.

Ключевое свойство: когда поиск в ширину **впервые** добавляет вершину в очередь, она получает свою итоговую дистанцию от старта (число рёбер). Никакой более короткий путь к ней уже найти нельзя — потому что все более короткие пути закончились бы раньше.

### Псевдокод

```
функция поиск_в_ширину(граф, старт):
    посещённые = {старт}
    очередь = новая_очередь()
    положить_в_конец(очередь, старт)
    
    пока очередь не пуста:
        вершина = взять_из_начала(очередь)
        обработать(вершина)
        для каждого соседа сосед из соседи(вершина):
            если сосед не в посещённые:
                добавить_в(посещённые, сосед)
                положить_в_конец(очередь, сосед)
```

### Пример пошагово

Возьмём такой граф (неориентированный):

```
        1 ─── 2
        │     │
        3 ─── 4 ─── 5
```

Список смежности:
- 1 → [2, 3]
- 2 → [1, 4]
- 3 → [1, 4]
- 4 → [2, 3, 5]
- 5 → [4]

Стартуем с вершины 1.

| Шаг | Вытащили | Очередь после | Посещённые |
|---|---|---|---|
| 0 | — | [1] | {1} |
| 1 | 1 | [2, 3] | {1, 2, 3} |
| 2 | 2 | [3, 4] | {1, 2, 3, 4} |
| 3 | 3 | [4] | {1, 2, 3, 4} (4 уже посещена) |
| 4 | 4 | [5] | {1, 2, 3, 4, 5} |
| 5 | 5 | [] | {1, 2, 3, 4, 5} |

Порядок обработки: `1 → 2 → 3 → 4 → 5`. Расстояния от вершины 1: вершина 1 на расстоянии 0, вершины 2 и 3 на расстоянии 1, вершины 4 и 5 на расстояниях 2 и 3 соответственно.

### Где применяется

- **Кратчайший путь в невзвешенном графе** — самая частая задача. Любой граф, где «стоимость» каждого ребра одинакова, читай: лабиринт, шахматный конь на доске, состояния головоломки.
- **Волновой алгоритм на сетке** — заливка области одного цвета, поиск пути в роботе, расчёт расстояний от пожара во всех клетках.
- **Уровневая обработка дерева** — обойти бинарное дерево по уровням сверху вниз.
- **Поиск ближайших N элементов** — например, найти ближайшие 100 страниц по ссылочной структуре.
- **Двусторонний поиск** — запускаем поиск в ширину одновременно с обоих концов и встречаемся посередине; это даёт огромное ускорение по сравнению с одним поиском.

### Тонкость про момент пометки «посещён»

Распространённая ошибка — помечать вершину посещённой не в момент **добавления** в очередь, а в момент **извлечения** из очереди. Если сделать так, одна и та же вершина может несколько раз попасть в очередь (через разных соседей), пока её не достали. Это всё ещё работает, но превращает время в худшем случае из O(V + E) в O(V × E) или хуже. Правильно — помечать сразу при добавлении.

## Поиск в глубину — подробный разбор

### Идея

Представь себе человека в лабиринте, который у каждой развилки выбирает первый попавшийся коридор, идёт по нему до конца и возвращается только когда упёрся в тупик или в уже посещённое место. Это и есть поиск в глубину.

### Две формы записи

**Рекурсивная** — короче и читабельнее, но опасна на больших графах: глубина рекурсии может превысить лимит интерпретатора (в Python по умолчанию 1000). Лечится либо явным увеличением лимита через `sys.setrecursionlimit`, либо переходом на итеративную форму.

**Итеративная** — использует обычный стек (массив). Не страдает от лимита рекурсии, но требует чуть аккуратнее реализации.

### Псевдокод (рекурсивная форма)

```
функция поиск_в_глубину(граф, вершина, посещённые):
    добавить_в(посещённые, вершина)
    обработать(вершина)
    для каждого соседа сосед из соседи(вершина):
        если сосед не в посещённые:
            поиск_в_глубину(граф, сосед, посещённые)
```

### Пример пошагово

Тот же граф. Стартуем с вершины 1, соседей берём в порядке списка смежности.

```
обход(1):
    отметили 1, обработали 1
    обход(2):
        отметили 2, обработали 2
        обход(4):
            отметили 4, обработали 4
            обход(3):  # 3 ещё не посещена
                отметили 3, обработали 3
                # сосед 1 — посещён, пропускаем
                # сосед 4 — посещён, пропускаем
            # вернулись из обхода(3)
            обход(5):
                отметили 5, обработали 5
            # вернулись из обхода(5)
        # вернулись из обхода(4)
    # вернулись из обхода(2)
    # сосед 3 — уже посещён
# готово
```

Порядок обработки: `1 → 2 → 4 → 3 → 5`. Заметь: до вершины 5 поиск в глубину «дотащил» путь длиной 4 ребра (1 → 2 → 4 → 3 → … стоп, 3 → 5 нет ребра, идём 1 → 2 → 4 → 5), хотя есть прямой путь 1 → 2 → 4 → 5 длиной 3. Это нормально: поиск в глубину не ищет кратчайший путь.

### Раскраска в три цвета (для ориентированных графов)

Для тонкого анализа — особенно для **поиска циклов в ориентированном графе** — используется раскраска вершин:

- **Белый** — вершина ещё не посещалась.
- **Серый** — вершина в данный момент находится в стеке рекурсии (обход её ещё не закончился).
- **Чёрный** — вершина и всё её поддерево полностью обработаны.

Если в процессе обхода мы встречаем ребро, ведущее в **серую** вершину — значит, в графе есть цикл. (Ребро ведёт «вверх» в дерево обхода, такие рёбра называют обратными.)

### Где применяется

- **Поиск компонент связности** — запускаем поиск в глубину из каждой непосещённой вершины, каждый запуск — отдельная компонента.
- **Топологическая сортировка** — порядок выхода из вершин (момент окончания их обработки) даёт обратный топологический порядок.
- **Поиск мостов и точек сочленения** — алгоритм Тарьяна на основе моментов входа и значений low-link.
- **Сильно связные компоненты ориентированного графа** — алгоритмы Тарьяна и Косараджу, оба основаны на поиске в глубину.
- **Перебор с возвратом** (backtracking) — комбинаторные задачи, головоломки, генерация перестановок и подмножеств. По сути это поиск в глубину по дереву состояний.
- **Генерация лабиринтов** — рекурсивный алгоритм случайного блуждания.

## Когда применять что

| Признак задачи | Что брать |
|---|---|
| Лабиринт, минимальное число шагов, «ближайшая» вершина, веса всех рёбер одинаковы | Поиск в ширину |
| Все варианты пути, перебор, рекурсивная структура (дерево разбора, дерево решений) | Поиск в глубину |
| Веса рёбер не одинаковы, но неотрицательные | Алгоритм Дейкстры (см. раздел 10) |
| Веса рёбер могут быть отрицательными | Алгоритм Беллмана-Форда |
| Кратчайшие пути между всеми парами вершин | Алгоритм Флойда-Уоршелла |
| Веса 0 и 1 | Модифицированный поиск в ширину на двусторонней очереди (deque) |

## Типичные ловушки

1. **Не отмечать посещённость вообще** — на графе с циклами обход уйдёт в бесконечность. Симптом: программа висит, память пухнет.
2. **Отмечать в момент извлечения, а не добавления в поиске в ширину** — дубли в очереди, время растёт квадратично.
3. **Глубокая рекурсия в Python** — `RecursionError` на цепочках длиннее 1000 вершин. Лечится `sys.setrecursionlimit(10**6)` или итеративной версией.
4. **Считать, что поиск в глубину даёт кратчайший путь** — нет, не даёт. Для длины пути в невзвешенном графе обязательно поиск в ширину.
5. **Забыть проверить связность** — если граф не связный, обход из одной вершины посетит только её компоненту. Чтобы посетить весь граф, нужно запускать обход из каждой непосещённой вершины в цикле.
6. **Перепутать ориентированный и неориентированный граф** — для ориентированного нужно явно хранить только исходящие рёбра. Для неориентированного при добавлении ребра (u, v) нужно положить v в список смежности u **и** u в список смежности v.

## Полезные вариации

- **Поиск в ширину из нескольких источников** — кладём в очередь сразу несколько стартовых вершин с расстоянием 0. Полезно когда нужно «расстояние до ближайшей точки интереса». Например, расстояние от каждой клетки до ближайшего источника воды на карте.
- **Двусторонний поиск в ширину** (bidirectional BFS) — запускаем одновременно из старта и из цели, останавливаемся когда волны встретились. Если граф большой и однородный, ускоряет поиск на порядки: вместо одной волны радиуса R две волны радиуса R/2.
- **Итеративное углубление** (iterative deepening DFS) — поиск в глубину с ограничением глубины d, повторяется для d = 1, 2, 3, … Сочетает память поиска в глубину и оптимальность поиска в ширину. Используется в шахматных движках.
- **Поиск в ширину на двусторонней очереди (0-1 BFS)** — работает на графах с весами 0 и 1. Рёбра веса 0 кладутся в начало очереди, рёбра веса 1 — в конец. Сложность та же O(V + E).
