# 07. Динамическое программирование

## Что это вообще такое

Динамическое программирование — это техника решения задач, в которой большая задача разбивается на меньшие подзадачи **того же типа**, и решения подзадач **сохраняются**, чтобы не пересчитывать их многократно. Слово «программирование» здесь — историческое и означает «составление таблицы», а не написание кода. Метод предложил Ричард Беллман в 1950-х годах.

Главная интуиция: если ты разбиваешь задачу на подзадачи и видишь, что одни и те же подзадачи возникают снова и снова в разных ветках перебора — кешируй их. Это превращает экспоненциальный по времени перебор в полиномиальный.

## Когда динамическое программирование применимо

Задача допускает решение через динамическое программирование, если у неё есть **оба** свойства:

1. **Оптимальная подструктура.** Оптимальное решение всей задачи строится из оптимальных решений подзадач. Например, кратчайший путь из A в C через промежуточную точку B состоит из кратчайшего пути из A в B и кратчайшего пути из B в C — нельзя улучшить общий путь, не улучшив одну из частей.
2. **Перекрывающиеся подзадачи.** Если рекурсивно расписать задачу, одни и те же подзадачи возникают многократно. Классический пример — наивная рекурсия для чисел Фибоначчи: `fib(5)` вызывает `fib(4)` и `fib(3)`, но `fib(4)` снова вызовет `fib(3)`, и так далее экспоненциально.

Если есть только оптимальная подструктура, но подзадачи **не** перекрываются — это парадигма «разделяй и властвуй» (например, сортировка слиянием), а не динамическое программирование.

## Два стиля реализации

### Сверху вниз — мемоизация

Пишешь рекурсивную функцию ровно так, как формулируется задача, и оборачиваешь её в кеш. При каждом вызове функция сначала смотрит в кеше, не считала ли она уже это значение; если да — возвращает сразу. Если нет — считает и сохраняет.

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    if n < 2: return n
    return fib(n-1) + fib(n-2)
```

**Плюсы.** Код читается практически как математическая формулировка задачи. Считаются только реально нужные подзадачи. Не нужно продумывать порядок заполнения таблицы — рекурсия сама знает.

**Минусы.** Глубокая рекурсия может переполнить стек. Хеш-таблица для кеша даёт оверхед по сравнению с массивом. На очень больших таблицах это всё ощутимо.

### Снизу вверх — табуляция

Заполняешь таблицу подзадач от базовых случаев к итоговому. Каждая клетка таблицы вычисляется ровно один раз, через значения, уже посчитанные ранее.

```python
def fib(n):
    if n < 2: return n
    a, b = 0, 1
    for _ in range(n - 1):
        a, b = b, a + b
    return b
```

**Плюсы.** Нет рекурсии — никаких переполнений стека. Доступ к массиву по индексу быстрее, чем по хеш-таблице. Часто можно сжать память: для чисел Фибоначчи нужно хранить только два последних значения, а не всю таблицу из n клеток.

**Минусы.** Нужно явно продумать порядок заполнения. На задачах со сложной структурой состояний это может быть нетривиально. Иногда считаются клетки, которые не повлияют на ответ.

## Шаги построения решения через динамическое программирование

Когда видишь задачу, проходишь по такому чек-листу:

1. **Определи состояние.** Что именно характеризует подзадачу? Минимальный набор переменных, по которым задача распадается на одинаковые подзадачи. Обычно состояние записывается как `dp[i]` или `dp[i][j]`. Например, для рюкзака состояние — «номер рассматриваемой вещи и оставшаяся вместимость».
2. **Определи базовые случаи.** Чему равно `dp` для тривиальных аргументов? Для Фибоначчи это `dp[0] = 0`, `dp[1] = 1`. Для расстояния редактирования — `dp[i][0] = i` (превратить i символов в пустую строку — i удалений).
3. **Выпиши переход.** Формула, выражающая `dp[i]` через клетки с меньшими индексами. Это сердце алгоритма. Часто переход — это «рассмотрим, чем заканчивается оптимальное решение, и переберём варианты».
4. **Определи ответ.** Какая клетка таблицы содержит ответ на исходную задачу? Часто это `dp[n]` или `dp[n][m]`, но не всегда.
5. **Оцени сложность.** Время = (число состояний) × (стоимость одного перехода). Память = (размер таблицы), часто можно сжать.

## Классические задачи

### Числа Фибоначчи

**Состояние.** `dp[i]` — i-е число Фибоначчи.
**База.** `dp[0] = 0`, `dp[1] = 1`.
**Переход.** `dp[i] = dp[i-1] + dp[i-2]`.
**Ответ.** `dp[n]`.
**Сложность.** Время O(n), память O(n) → сжимается до O(1).

Стоимость перехода — константа, поэтому вся работа — это n итераций.

### Подъём по лестнице

Лестница из n ступеней, на каждом шаге можно подняться на 1 или на 2 ступени. Сколько различных способов подняться?

**Состояние.** `dp[i]` — число способов добраться до i-й ступени.
**База.** `dp[0] = 1` (стоим в начале — один способ, ничего не делать), `dp[1] = 1`.
**Переход.** Чтобы попасть на i-ю ступень, последний шаг был либо с (i-1)-й, либо с (i-2)-й. Значит `dp[i] = dp[i-1] + dp[i-2]`.

Это в точности Фибоначчи (со сдвигом).

### Размен монет — минимальное число монет на сумму S

Дана сумма S и набор номиналов. Каждый номинал можно использовать неограниченное число раз. Найти минимум монет, чтобы собрать сумму S, или сообщить что невозможно.

**Состояние.** `dp[s]` — минимальное число монет, чтобы собрать сумму s.
**База.** `dp[0] = 0` (нулевая сумма собирается нулём монет). Все остальные клетки изначально равны бесконечности (пока не доказано обратное).
**Переход.** `dp[s] = min(dp[s - c] + 1)` по всем номиналам c, таким что c ≤ s. Это означает: «последняя положенная монета имела номинал c, а до неё мы собрали сумму s - c».
**Ответ.** `dp[S]`. Если он остался бесконечностью — собрать невозможно.
**Сложность.** Время O(S × len(coins)), память O(S).

Важно: жадный алгоритм (всё время класть самую крупную подходящую монету) работает только для канонических систем номиналов. Для произвольных номиналов он ошибается, и нужно динамическое программирование.

### Задача о рюкзаке 0/1

Есть n вещей, у каждой свой вес `wt[i]` и ценность `val[i]`. Рюкзак выдерживает суммарный вес не более W. Каждую вещь можно либо положить в рюкзак (один раз), либо не класть. Максимизировать суммарную ценность.

**Состояние.** `dp[i][w]` — максимальная ценность, которую можно набрать, используя только первые i вещей при ограничении весом w.
**База.** `dp[0][w] = 0` для всех w (нет вещей — нет ценности).
**Переход.** Для i-й вещи рассматриваем два варианта:
- **Не брать.** Тогда `dp[i][w] = dp[i-1][w]`.
- **Брать** (если она вообще влезает, то есть `wt[i] ≤ w`). Тогда `dp[i][w] = dp[i-1][w - wt[i]] + val[i]`.

Берём максимум из двух вариантов: `dp[i][w] = max(dp[i-1][w], dp[i-1][w - wt[i]] + val[i])`.

**Ответ.** `dp[n][W]`.
**Сложность.** Время O(n × W), память O(n × W) → сжимается до O(W).

**Тонкость со сжатием памяти.** Если переписать в виде одномерного массива `dp[w]`, нужно идти по w **справа налево**. Иначе одна и та же вещь может быть «положена» дважды (это уже был бы unbounded knapsack — рюкзак с неограниченным числом каждой вещи).

### Наибольшая общая подпоследовательность

Даны две строки a и b. Найти максимальную длину подпоследовательности, которая встречается и в a, и в b. Подпоследовательность — это символы, выбранные из строки в исходном порядке, но не обязательно подряд.

Пример: для `ABCBDAB` и `BDCABA` наибольшая общая подпоследовательность — `BCBA` или `BDAB`, длина 4.

**Состояние.** `dp[i][j]` — длина наибольшей общей подпоследовательности префиксов `a[:i]` и `b[:j]`.
**База.** `dp[0][j] = dp[i][0] = 0` (с пустой строкой нет общих символов).
**Переход.**
- Если `a[i-1] == b[j-1]`, то этот символ можно включить: `dp[i][j] = dp[i-1][j-1] + 1`.
- Иначе хотя бы один из этих символов в наибольшую общую подпоследовательность не входит, и `dp[i][j] = max(dp[i-1][j], dp[i][j-1])`.

**Ответ.** `dp[n][m]`.
**Сложность.** Время O(n × m), память O(n × m).

### Расстояние редактирования (расстояние Левенштейна)

Минимальное число операций (вставка, удаление, замена одного символа), чтобы превратить строку a в строку b.

**Состояние.** `dp[i][j]` — минимум операций, чтобы превратить `a[:i]` в `b[:j]`.
**База.** `dp[i][0] = i` (i удалений), `dp[0][j] = j` (j вставок).
**Переход.** Если `a[i-1] == b[j-1]`, последний символ совпадает, и операция не нужна: `dp[i][j] = dp[i-1][j-1]`. Иначе перебираем три возможные последние операции:
- **Удалить** `a[i-1]`: `dp[i-1][j] + 1`.
- **Вставить** `b[j-1]`: `dp[i][j-1] + 1`.
- **Заменить** `a[i-1]` на `b[j-1]`: `dp[i-1][j-1] + 1`.

Берём минимум.

**Сложность.** Время и память O(n × m).

### Наибольшая возрастающая подпоследовательность

Дан массив. Найти длину наибольшей строго возрастающей подпоследовательности.

Пример: для `[10, 9, 2, 5, 3, 7, 101, 18]` ответ — 4 (одна из таких подпоследовательностей `2, 5, 7, 101`).

**Простое решение.** `dp[i]` — длина наибольшей возрастающей подпоследовательности, заканчивающейся в i-м элементе. Переход: `dp[i] = 1 + max(dp[j])` по всем j < i, таким что `a[j] < a[i]`. Сложность O(n²).

**Быстрое решение через бинарный поиск.** Поддерживаем массив `tails`, где `tails[k]` — минимальный возможный последний элемент возрастающей подпоследовательности длины k+1. Для каждого нового элемента бинпоиском находим, куда его подставить. Сложность O(n log n).

### Перемножение цепочки матриц

Даны размерности n матриц. Найти такой порядок перемножения (расстановки скобок), чтобы суммарное число умножений было минимальным.

**Состояние.** `dp[i][j]` — минимум умножений, чтобы перемножить матрицы с i-й по j-ю.
**Переход.** Перебираем точку k, в которой делим цепочку: `dp[i][j] = min(dp[i][k] + dp[k+1][j] + p[i-1] * p[k] * p[j])`.
**Сложность.** Время O(n³), память O(n²).

### Задача о разбиении

Можно ли разбить массив целых чисел на два подмножества с равной суммой? Это частный случай задачи о подмножестве с заданной суммой и решается ровно как 0/1 рюкзак.

## Восстановление ответа

Часто помимо размера/стоимости оптимума нужен сам набор: какие вещи положили в рюкзак, какая именно подпоследовательность является наибольшей общей, какие операции редактирования. Решается одним из двух способов:

- **Параллельная таблица «откуда пришли»**: для каждой клетки запоминаем, какой переход дал её значение. После заполнения таблицы идём по ней назад от ответа к базе.
- **Восстановление по самой таблице** без дополнительной памяти: смотрим на значения соседних клеток и понимаем, какой переход привёл сюда. Работает не всегда, но часто экономит память.

## Типичные ловушки

1. **Состояние слишком жирное.** Если в состояние попало больше параметров, чем строго нужно, — память растёт катастрофически. Думай: какие именно параметры влияют на оптимальность остатка задачи?
2. **Неправильный порядок заполнения.** Переход обращается к ещё не посчитанным клеткам. Признак — мусор или нули в ответе. Лечится либо мемоизацией (она сама определит порядок), либо аккуратным анализом зависимостей.
3. **Путаница 0/1 рюкзака и unbounded.** В 0/1 каждая вещь не более одного раза, идём по w справа налево при сжатии. В unbounded — вещь можно брать сколько угодно, идём слева направо.
4. **Граничные индексы.** Особенно при работе с префиксами строк: `a[i-1]` или `a[i]`? Если `dp[i][j]` обозначает префиксы длины i и j, то символ берётся под индексом i-1.
5. **Бесконечность в начальной таблице.** Для задач на минимум нужно явно инициализировать недостижимые клетки большим числом или специальным маркером, иначе `min` не сработает.
6. **Переполнение целых чисел.** Длинные числа Фибоначчи, число способов разменять большую сумму — могут вылезти за пределы int64. В Python это не проблема (целые произвольной длины), в Go — да.
