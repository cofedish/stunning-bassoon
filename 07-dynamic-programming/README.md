# 07. Динамическое программирование

ДП = разбиение задачи на подзадачи + сохранение их решений, чтобы не пересчитывать.

## Когда применимо

Задача допускает ДП, если:
1. **Оптимальная подструктура** — оптимум целого собирается из оптимумов частей.
2. **Перекрывающиеся подзадачи** — одни и те же подзадачи возникают в разных ветках перебора.

Если есть только (1) без (2) — это «разделяй и властвуй» (например, merge sort), а не ДП.

## Два стиля

### Top-down (мемоизация)

Пишешь рекурсию «как думаешь», и кеш-декоратор / словарь запоминает уже посчитанное.

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    if n < 2: return n
    return fib(n-1) + fib(n-2)
```

Плюсы: код читается как формулировка задачи. Минусы: глубокий стек, оверхед на хеш-таблицу.

### Bottom-up (табуляция)

Заполняешь таблицу от базовых случаев к итоговому.

```python
def fib(n):
    if n < 2: return n
    a, b = 0, 1
    for _ in range(n - 1):
        a, b = b, a + b
    return b
```

Плюсы: быстрее, меньше памяти (часто можно держать только 1-2 строки таблицы). Минусы: нужно явно продумать порядок заполнения.

## Шаги построения ДП-решения

1. **Состояние** — `dp[i]` (или `dp[i][j]`) — что именно мы храним. Минимум переменных, по которым задача распадается на одинаковые подзадачи.
2. **База** — значения `dp` для тривиальных случаев.
3. **Переход** — формула, выражающая `dp[i]` через меньшие индексы.
4. **Ответ** — какое значение из таблицы вернуть.
5. **Сложность** — `(число состояний) × (стоимость одного перехода)`.

## Классические задачи

### Числа Фибоначчи
- Состояние: `dp[i]` — i-е число.
- Переход: `dp[i] = dp[i-1] + dp[i-2]`.
- O(n) время, O(1) память.

### Подъём по лестнице (n ступеней, можно шагать на 1 или 2)
- `dp[i] = dp[i-1] + dp[i-2]`. То же что Фибоначчи.

### Размен монет (минимум монет на сумму S)
- Состояние: `dp[s]` — минимум монет, чтобы собрать сумму `s`.
- База: `dp[0] = 0`, остальное `+inf`.
- Переход: `dp[s] = min(dp[s - c] + 1 for c in coins if c <= s)`.
- O(S × len(coins)).

### 0/1 рюкзак (вещи берём 0 или 1 раз)
- Состояние: `dp[i][w]` — макс. ценность из первых `i` вещей при ограничении весом `w`.
- Переход: `dp[i][w] = max(dp[i-1][w], dp[i-1][w - wt[i]] + val[i])` (если влезает).
- O(N × W) время и память. Память сжимается до O(W) если идти по `w` справа налево.

### LCS — наибольшая общая подпоследовательность строк a, b
- Состояние: `dp[i][j]` — длина LCS префиксов `a[:i]` и `b[:j]`.
- Переход:
  - если `a[i-1] == b[j-1]`: `dp[i][j] = dp[i-1][j-1] + 1`
  - иначе: `dp[i][j] = max(dp[i-1][j], dp[i][j-1])`
- O(n × m).

### Расстояние Левенштейна (edit distance)
- `dp[i][j]` — минимум операций (вставка/удаление/замена), чтобы превратить `a[:i]` в `b[:j]`.
- Переход: рассмотри 3 варианта последней операции.

### LIS — наибольшая возрастающая подпоследовательность
- Простой ДП: `dp[i] = 1 + max(dp[j] for j < i if a[j] < a[i])`. O(n²).
- Бинпоиск + терпеливая раскладка: O(n log n).

## Типичные ловушки

- **Состояние слишком жирное** — экспонента в памяти. Думай: какие именно параметры нужны для перехода?
- **Неправильный порядок заполнения** — переход обращается к ещё не посчитанным клеткам.
- **0/1 рюкзак vs unbounded** — в unbounded идём по `w` слева направо, в 0/1 — справа налево.
- **Восстановление ответа** — если нужен не только размер, но и сам путь/набор, сохраняй «откуда пришли».
