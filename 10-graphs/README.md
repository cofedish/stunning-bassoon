# 10. Алгоритмы на графах

## Граф как универсальная модель

Граф — это математический объект, состоящий из множества **вершин** и множества **рёбер**, каждое из которых соединяет пару вершин. Формально граф записывают как `G = (V, E)`, где V — множество вершин, E — множество рёбер.

Графы повсюду. Они моделируют:
- Дорожную сеть: перекрёстки — вершины, дороги — рёбра, длина дороги — вес.
- Социальные сети: пользователи — вершины, дружбы — рёбра.
- Зависимости задач: задачи — вершины, ребро A → B означает «A надо сделать перед B».
- Состояния игры: каждая позиция — вершина, ход — ребро. Поиск выигрышной стратегии — поиск пути в этом графе.
- Веб: страницы — вершины, ссылки — ориентированные рёбра.
- Электронные схемы, химические молекулы, последовательности ДНК — всё это естественно описывается графами.

## Терминология

| Термин | Определение |
|---|---|
| Ориентированный граф (digraph) | Каждое ребро имеет направление: ребро от u к v не то же самое, что от v к u |
| Неориентированный граф | Рёбра двунаправленные: ребро `(u, v)` соединяет u и v без приоритета |
| Взвешенный граф | Каждому ребру сопоставлено число — вес (стоимость, длина, время) |
| Степень вершины | Число рёбер, инцидентных этой вершине. В ориентированном графе различают входящую и исходящую степень |
| Путь | Последовательность вершин, соединённых рёбрами по порядку |
| Простой путь | Путь, в котором ни одна вершина не повторяется |
| Цикл | Путь, в котором первая и последняя вершины совпадают |
| Ориентированный ациклический граф (DAG) | Ориентированный граф без циклов |
| Связный граф | Между любой парой вершин существует путь |
| Сильно связный | Для ориентированного графа: между любой парой вершин есть путь в обе стороны |
| Дерево | Связный неориентированный граф без циклов. На V вершинах ровно V−1 рёбер |
| Лес | Несвязный граф, каждая компонента которого — дерево |

## Способы хранения графа

Выбор представления влияет на скорость алгоритмов и расход памяти.

**Матрица смежности.** Двумерный массив размера V × V. `M[u][v] = 1`, если ребро есть, и 0 иначе. Для взвешенного графа в клетке хранится вес.
- Память: O(V²).
- Проверка наличия ребра между конкретной парой: O(1).
- Перебор всех соседей вершины: O(V).
- Когда брать: плотный граф (E близко к V²), частые запросы вида «есть ли ребро между u и v».

**Список смежности.** Массив списков: для каждой вершины — список её соседей.
- Память: O(V + E).
- Проверка наличия ребра: O(степень вершины).
- Перебор всех соседей: O(степень вершины).
- Когда брать: разрежённый граф (E намного меньше V²), нужны быстрые обходы.

**Список рёбер.** Просто массив пар (или троек, если есть веса).
- Память: O(E).
- Когда брать: алгоритмы, которые перебирают рёбра целиком (например, Краскал для минимального остовного дерева).

В большинстве задач — список смежности.

## Поиск в ширину и поиск в глубину

Подробно разобраны в разделе 1. Здесь напомним: оба алгоритма работают за O(V + E) и являются основой для большинства более сложных алгоритмов на графах. Поиск в ширину естественно даёт кратчайший путь в невзвешенном графе. Поиск в глубину используется для топологической сортировки, поиска компонент связности, поиска мостов и точек сочленения, поиска сильно связных компонент.

## Топологическая сортировка ориентированного ациклического графа

**Задача.** Дан ориентированный ациклический граф. Нужно расположить вершины в линейный порядок так, чтобы для каждого ребра u → v вершина u шла раньше v.

**Применение.** Порядок выполнения задач с зависимостями (системы сборки, миграции БД, расписание курсов). Порядок компиляции модулей. Планирование пайплайна.

**Алгоритм Кана через входящие степени.**

1. Подсчитать для каждой вершины её входящую степень — число входящих рёбер.
2. Положить в очередь все вершины с входящей степенью 0.
3. Пока очередь не пуста: достать вершину u, добавить её в результат. Для каждого исходящего ребра u → v уменьшить входящую степень вершины v. Если она стала 0 — положить v в очередь.
4. Если в результате все V вершин — порядок построен. Если меньше — в графе есть цикл, и топологический порядок не существует.

**Сложность.** Время O(V + E), память O(V).

**Альтернатива через поиск в глубину.** Запускаем поиск в глубину из каждой непосещённой вершины. В момент **выхода** из вершины (когда обработали всех её потомков) добавляем её в начало списка результата. После прогонки список содержит топологический порядок.

## Кратчайшие пути

Здесь и далее «кратчайший путь» — это путь с минимальной суммой весов рёбер. Если все веса равны 1, это совпадает с минимальным числом рёбер.

### Алгоритм Дейкстры — от одной вершины ко всем (только при неотрицательных весах)

**Идея.** Поддерживаем массив `dist[v]` — текущая лучшая известная оценка расстояния от стартовой вершины. Изначально `dist[start] = 0`, остальные равны бесконечности.

На каждом шаге:
1. Берём непосещённую вершину с **минимальным** значением `dist`. Обозначим её u.
2. Помечаем u как посещённую — её расстояние теперь окончательное.
3. **Релаксация.** Для каждого ребра u → v с весом w: если `dist[u] + w < dist[v]`, то обновляем `dist[v] = dist[u] + w`.

Повторяем пока не обработаны все вершины.

**Эффективная реализация.** Используем минимум-кучу (priority queue). Каждый раз, когда расстояние до вершины обновляется, кладём в кучу новую запись. При извлечении проверяем, актуальна ли она — если значение в куче больше текущего `dist`, пропускаем.

**Псевдокод.**
```
dist[start] = 0
heap = [(0, start)]

пока heap не пуста:
    (d, u) = достать_минимум(heap)
    если d > dist[u]: продолжить                # устаревшая запись
    для каждого ребра (u, v, w) из исходящие(u):
        новое_расстояние = d + w
        если новое_расстояние < dist[v]:
            dist[v] = новое_расстояние
            положить_в_кучу(heap, (новое_расстояние, v))
```

**Сложность.** O((V + E) log V) с двоичной кучей. С кучей Фибоначчи — O(E + V log V), но на практике почти не используется из-за сложной реализации.

**Почему не работает с отрицательными весами.** Дейкстра жадно фиксирует расстояния и больше их не пересматривает. Отрицательное ребро может позже улучшить уже зафиксированное расстояние, но Дейкстра этого не заметит.

### Алгоритм Беллмана-Форда — отрицательные веса разрешены

**Задача.** Кратчайшие пути от одной вершины ко всем при произвольных весах рёбер, в том числе отрицательных. Если в графе достижим отрицательный цикл — алгоритм его обнаруживает и сигнализирует, что кратчайший путь не определён (можно ходить по циклу бесконечно, делая путь сколь угодно отрицательным).

**Идея.** Простая: V−1 раз проходим по всем рёбрам и пытаемся релаксировать каждое. После V−1 прогонок все расстояния гарантированно будут оптимальны (если нет отрицательного цикла). На V-й прогонке проверяем: если есть рёбра, которые ещё уменьшают расстояние, — есть отрицательный цикл.

**Псевдокод.**
```
dist[start] = 0, остальные = ∞

повторить V-1 раз:
    для каждого ребра (u, v, w):
        если dist[u] + w < dist[v]:
            dist[v] = dist[u] + w

# проверка на отрицательный цикл
для каждого ребра (u, v, w):
    если dist[u] + w < dist[v]:
        вернуть "есть отрицательный цикл"
```

**Сложность.** O(V × E). Медленнее Дейкстры, но универсальнее.

### Алгоритм Флойда-Уоршелла — кратчайшие пути между всеми парами вершин

**Задача.** Найти `dist[i][j]` для всех пар.

**Идея.** Поэтапно разрешаем использовать как промежуточные сначала только вершину 0, потом 0 и 1, потом 0, 1, 2 и так далее. На k-м шаге `dist[i][j]` — длина кратчайшего пути из i в j, использующего только вершины из множества `{0, 1, ..., k}` как промежуточные.

**Переход.** При добавлении новой промежуточной вершины k путь из i в j либо не использует k (тогда длина не меняется), либо проходит через k (тогда длина = `dist[i][k] + dist[k][j]`):
```
dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])
```

**Псевдокод.**
```
для k от 0 до V-1:
    для i от 0 до V-1:
        для j от 0 до V-1:
            если dist[i][k] + dist[k][j] < dist[i][j]:
                dist[i][j] = dist[i][k] + dist[k][j]
```

**Сложность.** Время O(V³), память O(V²). Подходит для маленьких или плотных графов (V до нескольких сотен). Работает с отрицательными весами без отрицательных циклов.

### Алгоритм A*

Развитие Дейкстры с эвристикой. Кроме `dist[v]` (фактическое расстояние от старта) учитывает `h(v)` — оценку оставшегося расстояния до цели. Извлекает из кучи вершину с минимальным `dist[v] + h(v)`.

Если эвристика **допустимая** (никогда не переоценивает оставшееся расстояние) — A* находит оптимальный путь и обычно намного быстрее обычной Дейкстры. На сетке хорошая эвристика — манхэттенское расстояние или евклидово.

## Минимальное остовное дерево

**Задача.** Дан связный неориентированный взвешенный граф. Найти подмножество рёбер, которое связывает все вершины и имеет минимальную суммарную стоимость. Такое подмножество всегда является деревом (V−1 ребро без циклов) и называется минимальным остовным деревом (Minimum Spanning Tree).

**Применение.** Прокладка дешёвой сети дорог/трубопроводов/электрических линий между городами. Кластеризация (минимальное остовное дерево с последующим удалением k−1 самых длинных рёбер даёт k кластеров). Аппроксимация задачи коммивояжёра.

### Алгоритм Краскала

**Идея.** Сортируем все рёбра по возрастанию веса и пытаемся добавлять их по очереди. Ребро добавляем, если его концы пока в **разных** компонентах связности (то есть оно не образует цикл с уже добавленными). Останавливаемся, когда добавили V−1 ребро.

**Структура данных.** Система непересекающихся множеств (Union-Find / Disjoint Set Union). См. отдельный раздел ниже.

**Псевдокод.**
```
отсортировать рёбра по возрастанию веса
dsu = новая_структура_DSU(V)
mst = []

для каждого ребра (u, v, w) в отсортированном порядке:
    если найти(u) != найти(v):
        объединить(u, v)
        добавить (u, v, w) в mst
        если len(mst) == V-1: выйти

вернуть mst
```

**Сложность.** O(E log E) на сортировку плюс O(E α(V)) на операции с системой непересекающихся множеств. Так как α(V) — это обратная функция Аккермана и для всех практических V меньше 5, по сути сложность O(E log E).

### Алгоритм Прима

**Идея.** В отличие от Краскала, который растит лес и сливает его, Прим растит **одно** дерево. Начинаем с одной вершины. На каждом шаге добавляем минимальное по весу ребро, соединяющее уже выбранные вершины с ещё не выбранными.

**Структура данных.** Минимум-куча, хранящая «кандидатов» — рёбра, ведущие из дерева наружу.

**Сложность.** O(E log V) с двоичной кучей. На плотных графах часто чуть быстрее Краскала, на разрежённых — наоборот.

## Система непересекающихся множеств

Структура данных, которая поддерживает разбиение n элементов на непересекающиеся множества и две операции:
- **Найти (Find).** По элементу x вернуть представителя его множества.
- **Объединить (Union).** Объединить множества двух элементов.

**Реализация — массив родителей.** Каждое множество представляется как «дерево», в массиве для каждого элемента хранится индекс его родителя. Корень дерева — представитель.

**Эвристики.** Без эвристик простая реализация даёт O(n) на операцию в худшем случае. С двумя стандартными эвристиками — почти O(1):
- **Объединение по рангу или по размеру.** При объединении делаем родителем меньшее дерево, а не наоборот.
- **Сжатие пути.** При вызове `find(x)` все вершины на пути к корню переподвешиваем непосредственно к корню. На следующих вызовах путь будет короче.

С обеими эвристиками амортизированная сложность операции — O(α(n)), где α — обратная функция Аккермана. Это растёт настолько медленно, что на любых практических n меньше 5.

**Применение.** Алгоритм Краскала, проверка связности при онлайн-добавлении рёбер, оффлайн-обработка запросов на графах, объединение множеств в кластеризации.

## Поиск циклов

### В неориентированном графе

Запускаем поиск в глубину. Если в процессе из вершины u видим ребро в посещённую вершину v, и v **не родитель** u в дереве обхода, — нашли цикл. Если v родитель — это просто то ребро, по которому мы пришли в u, никакого цикла нет.

### В ориентированном графе

Используем раскраску в три цвета:
- Белый — вершина не посещалась.
- Серый — вершина в текущей ветке рекурсии (обход её ещё идёт).
- Чёрный — вершина и все её потомки полностью обработаны.

Если из обрабатываемой вершины ведёт ребро в **серую** — нашли цикл (это ребро ведёт назад в текущую цепочку рекурсии).

## Сильно связные компоненты ориентированного графа

**Сильно связная компонента** — это максимальное по включению множество вершин, в котором между любой парой вершин есть путь (в обе стороны).

### Алгоритм Косараджу

1. Запустить поиск в глубину на исходном графе. Запомнить порядок выхода из вершин.
2. Построить транспонированный граф (все рёбра развёрнуты).
3. Запустить поиск в глубину на транспонированном графе, обходя вершины в порядке, **обратном** порядку выхода из шага 1. Каждый запуск даёт одну сильно связную компоненту.

**Сложность.** O(V + E).

### Алгоритм Тарьяна

Однопроходный, тоже O(V + E), не требует строить транспонированный граф. Идея — поиск в глубину с поддержкой стека вершин и значений low-link, которые показывают, до какой минимальной вершины можно добраться обратными рёбрами.

## Шпаргалка «что брать под задачу»

| Задача | Алгоритм | Сложность |
|---|---|---|
| Кратчайший путь в невзвешенном графе | Поиск в ширину | O(V + E) |
| Кратчайший путь, веса 0 и 1 | Двусторонняя очередь BFS | O(V + E) |
| Кратчайший путь, веса неотрицательные | Алгоритм Дейкстры | O((V+E) log V) |
| Кратчайший путь, любые веса | Алгоритм Беллмана-Форда | O(V × E) |
| Все пары вершин | Алгоритм Флойда-Уоршелла | O(V³) |
| Кратчайший путь к одной цели с эвристикой | A* | зависит от эвристики |
| Минимальное остовное дерево | Краскал или Прим | O(E log V) |
| Цикл в неориентированном графе | Поиск в глубину с проверкой родителя | O(V + E) |
| Топологическая сортировка / цикл в ориентированном | Алгоритм Кана или DFS с цветами | O(V + E) |
| Связность онлайн | Система непересекающихся множеств | почти O(1) на операцию |
| Сильно связные компоненты | Тарьян или Косараджу | O(V + E) |
